Calculation log

Every calculation records its full basis, not just its answer. This is what makes a planning number defensible months after it was produced.

Open it by searching for Inventory Planning Calculation Log, or from the setup page, the worksheet, or Item Card → Inventory Planning → Calculation Log — which filters it to that item.

What each entry records

GroupFields
Identity Calculation type, item, date and time, user
Demand Average daily demand, standard deviation, observations, ADI, CV², demand pattern
Lead time Days, standard deviation, and the source the value came from
Safety stock inputs Service level applied, and the Z-score derived from it
EOQ inputs Annual demand, unit cost, holding cost, ordering cost
Outcome Raw result, final result, previous value, whether it was applied, result code, recommended policy, note

Calculation types

  • Safety Stock, Reorder Point, EOQ, Maximum Inventory — the four value calculators
  • Policy Advice — a demand classification and recommendation
  • Dynamic Supply — a value computed during a planning run by the optional dynamic provider, so planning-time values are as traceable as batch ones

Three questions it answers

“Why is this item's reorder point this number?”

Filter to the item, open the most recent Reorder Point entry. Average daily demand times lead time, plus safety stock — with every input listed, including which source the lead time came from.

“What was it before?”

The Previous Value field on every entry. You can reconstruct an item's whole planning history from the log.

“Why did nothing happen for this item?”

Entries are written even when no value is produced. The Result Code says which check stopped it and the Note explains — see Troubleshooting.

Set a retention policy

The log grows by one row per item per calculator per run.

A nightly run across 5,000 items writes roughly 25,000 rows a night. Set a retention policy.

The log is registered with the standard Business Central Retention Policy module, so this takes a minute:

  1. Search for Retention Policies
  2. New, and choose the table GSO Calculation Log
  3. Set a retention period — 90 days is a sensible start
  4. Enable the policy

Without a policy, nothing is ever deleted. Turning off Log Calculation History in setup stops the writes entirely, but you lose the audit trail — a retention policy is almost always the better answer.
