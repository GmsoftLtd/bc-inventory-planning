Setup reference

Search for Inventory Planning Setup, or find it under Manual Setup. One page configures all four calculators.

General

These settings apply to every calculator.

FieldDefaultWhat it does
Demand History Window (Days)365 Calendar days of history to analyse, ending on the work date. Range 30–1095. A shorter window reacts faster to change but is noisier; a longer one is stabler but lags.
Min Demand Observations20 Minimum number of days with demand before a result is produced. Below this the item reports Insufficient Demand Data. Minimum 3. This counts days, not transaction lines.
Round Up Results to Whole UnitsYes Round results up to whole units. Turn off for items measured in kilograms, litres or metres.
Log Calculation HistoryYes Write an entry to the calculation log for every calculation. Leaving this on is what makes results auditable.
Skip Make-to-Order ItemsYes Skip items whose replenishment is make-to-order. Their supply is driven by the order that demands them, not by a reorder point.
Fallback Lead Time (Days)7 Used when neither receipt history nor the item's Lead Time Calculation yields a lead time.
Count Consumption as DemandNo Count production and assembly consumption as demand alongside sales. Turn this on in manufacturing companies, or purchased components will report zero demand.
Trend Warning Threshold % (0 = off)30 Warn in the calculation note when recent demand deviates from the window average by more than this. Set 0 to disable.

Safety stock

FieldDefaultWhat it does
Default Service Level %95 Probability of not stocking out during a replenishment cycle. Range 70–99.99. Can be overridden per item.
Write Safety Stock to ItemYes Turn off to calculate and log without writing anything to items — useful while you are evaluating.
Service level is not linear in cost.

Moving from 95% to 99% roughly doubles the buffer. Raise it for the items where a stockout is expensive, not across the board — that is what the per-item override is for.

Reorder point

FieldDefaultWhat it does
Add Safety Stock to Reorder PointYes Include the freshly calculated safety stock in the reorder point, rather than the value stored on the item.
Write Reorder Point to ItemYesTurn off to preview only.
Set Policy to Fixed Reorder Qty. when NoneYes Give items with no reordering policy one, so the calculated reorder point actually does something. Suppressed for an item when the advisor recommends a different policy.
Write Maximum Inventory (ROP + EOQ) for Maximum Qty. ItemsYes Set the order-up-to level for items on the Maximum Qty. policy.

EOQ

FieldDefaultWhat it does
Ordering Cost (S)50 Cost of placing one order — administration, receiving, inspection — in your local currency. This is the single input most worth getting right.
Holding Rate0.25 Annual cost of holding one unit as a fraction of unit cost. 0.25 means 25% a year, covering capital, storage, insurance and obsolescence. Range 0–1.
Maximum EOQ (Months of Demand)6 Cap on the result. Stops a cheap, high-volume item from ordering two years of stock. Minimum 0.5. When the cap binds, the result code is Cap Applied.
EOQ Write TargetReorder Quantity Or Order Multiple, if you would rather the planning engine round order sizes than fix them.
Unit Cost SourceLast Direct Cost Or Standard Cost or Unit Cost. Pick the one your items actually populate.
Write EOQ to ItemYesTurn off to preview only.

Policy advisor

FieldDefaultWhat it does
Intermittent ADI Threshold1.32 Average Demand Interval above which demand counts as intermittent. The standard Syntetos–Boylan value.
Erratic CV-Squared Threshold0.49 Squared coefficient of variation above which demand size counts as erratic. Also Syntetos–Boylan.
Treat Shelf Life as Maximum Qty.Yes Items with an Expiration Calculation are steered to the Maximum Qty. policy so standing stock is capped.
Auto-Update Item Reordering PolicyNo Whether an applied advice run writes the recommended policy to the item. Off by default. Recommendations are logged either way — turn this on only once you trust the advice.

Auto-update only ever writes Fixed Reorder Qty., Maximum Qty. or Lot-for-Lot. It never flips an item to Order automatically: that is a sourcing decision, not a statistical one.

Planning engine integration

FieldDefaultWhat it does
Supply Values at Planning Time (Dynamic)No Supplies freshly calculated values to the planning engine during a planning run, instead of relying on whatever the last batch run wrote to the item.
Verify the dynamic provider on a sandbox first.

Run a regenerative plan for one item, confirm the requisition line reflects the calculated values, and check that a Dynamic Supply entry appears in the calculation log. Real Stockkeeping Units are never modified, items that cannot be calculated fall back to their stored values, and order modifiers stay under the planning engine's control.
