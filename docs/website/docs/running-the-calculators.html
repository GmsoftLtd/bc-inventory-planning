Running the calculators

Four ways to run: one item, a filtered set, a reviewed worksheet, or unattended on a schedule.

One item — from the Item Card

Item Card → Inventory Planning

ActionWhat it does
Calculate All Planning ValuesEverything, in dependency order
Calculate Safety StockSafety stock only
Calculate Reorder PointReorder point only
Calculate EOQEOQ only
Advise Reordering PolicyClassifies demand and recommends a policy
Calculation LogOpens the log filtered to this item

Each action reports its result and its reasoning. Whether the value reaches the item depends on the matching Write … to Item switch in setup.

Why “Calculate All” is not just the four actions in a row.

It runs them in dependency order — policy advice, safety stock, reorder point, EOQ, maximum inventory — and feeds the reorder point the freshly calculated safety stock rather than whatever is stored on the item. Running the individual actions out of order can build a reorder point on a stale safety stock.

It also suppresses the “Set Policy to Fixed Reorder Qty. when None” default for an item whose advice recommends something else, so one run never stamps a policy its own advice contradicts.

A filtered set — from the Item List

Item List → Inventory Planning

ActionWhat it does
Planning WorksheetOpens the preview worksheet
Calculate All (Selected/Filtered Items)Runs everything and applies, after confirming the item count
Advise Policy (Selected/Filtered Items)Classifies demand and logs recommendations

Scope: if you have selected more than one row, the selected rows win. Otherwise the current filter on the list defines the scope. Non-inventory, blocked and excluded items are skipped automatically.

Long runs commit every 100 items, so an interrupted run keeps the work already done.

Bulk actions apply immediately.

They write to items after a single confirmation. If you want to see the numbers before they land, use the Planning Worksheet instead — that is what it exists for.

Unattended — Job Queue

Inventory Planning Setup → Create Job Queue Entry creates a recurring entry that runs every day at 03:00, created on hold. Review the schedule, then set it to Ready.

The Parameter String on the entry selects what runs:

ValueRuns
ALL (default, also used when empty)Everything, in dependency order
SAFETYSTOCKSafety stock only
REORDERPOINTReorder point only
EOQEOQ only
ADVISORPolicy advice only

Create several entries with different parameters and schedules if that suits you — for example policy advice weekly, safety stock nightly.

Scheduled runs apply to every eligible item.

Protect any item whose planning values a person maintains by hand: tick Exclude from Inventory Planning on the item card.

At planning time — the dynamic provider

Optionally, the app can supply freshly calculated values to the planning engine during a planning run, instead of relying on whatever the last batch run wrote. Off by default; see Setup reference before enabling it.
